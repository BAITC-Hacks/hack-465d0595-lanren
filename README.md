+# Бизнесмен Ивентс
+
+**Из короткой идеи мероприятия — в понятную задачу для студенческой команды.**
+
+Хакатонный MVP команды **Lanren** по кейсу **МНВО — AI Sana**: качество описания бизнес-задач и открытый выбор команд.
+
+## 1. О проекте
+
+Бизнес часто описывает задачу одной фразой: «Хотим провести мероприятие, нужны студенты». Команде непонятны объём работы, сроки, доступные ресурсы, оплата и ожидаемый результат.
+
+**Бизнесмен Ивентс** помогает заказчику уточнить идею с помощью ИИ, подготовить карточку задачи, оценить полноту описания и опубликовать её в каталоге. Студенты самостоятельно выбирают интересные задачи и отправляют предложения.
+
+Для MVP выбрана конкретная область — **организация мероприятий**: открытых уроков, мастер-классов, встреч и небольших событий. Студенты могут помогать с регистрацией, навигацией участников, коммуникациями и координацией.
+
+**Для кого:**
+
+- **Бизнес и организаторы:** сформулировать понятное задание и получить отклики.
+- **Студенческие команды:** найти практическую задачу с обозначенными условиями и предложить свой план.
+
+## 2. Что реализовано
+
+| Возможность | Реализация в MVP |
+| --- | --- |
+| Описание идеи | Форма первоначального описания мероприятия |
+| Уточняющие вопросы | ИИ формирует до 7 вопросов по недостающим условиям |
+| Подготовка карточки | ИИ объединяет описание и ответы в название и структурированный текст |
+| Ручное редактирование | Название и описание можно изменить перед публикацией |
+| Выявление пробелов | Карточка содержит список условий, требующих уточнения |
+| Рейтинг готовности | Оценка полноты по 8 критериям, итог от 0 до 100 и объяснения |
+| Автосохранение | Черновик и ответы сохраняются в текущем браузере |
+| Новая задача | Кнопка очищает текущий черновик после подтверждения |
+| Публикация | Карточка записывается в Supabase и становится доступна в каталоге |
+| Каталог | Просмотр опубликованных задач и полного описания |
+| Отклик команды | Название команды, предложение и контакт сохраняются в базе |
+| Проверки при отклике | Нельзя откликнуться на свою задачу; предусмотрена уникальность отклика пользователя на задачу |
+| Интерфейс | Русский язык, адаптивная вёрстка, тёмная тема с лаймовыми акцентами |
+
+**Важно:** текущая версия доводит сценарий до сохранения отклика. Кабинет просмотра откликов и выбор команды заказчиком — следующий этап разработки.
+
+## 3. Как работает решение
+
+1. **Заказчик вводит идею.** Например: «Хотим провести открытый урок по ИИ для студентов. Нужна помощь с регистрацией и координацией».
+2. **ИИ задаёт вопросы.** Уточняет цель, аудиторию, дату, площадку, бюджет, ресурсы и границы ответственности.
+3. **Заказчик отвечает.** Неизвестные условия можно оставить нерешёнными — система отмечает пробелы.
+4. **ИИ готовит карточку.** Объединяет исходную идею и ответы в структурированный текст.
+5. **Заказчик проверяет результат.** Может исправить формулировки и запросить оценку готовности.
+6. **Карточка публикуется.** Название и описание сохраняются в базе и появляются в открытом каталоге.
+7. **Команда отправляет отклик.** Указывает свой опыт, план работы и контакт.
+
+Система не назначает исполнителей автоматически. В целевом сценарии окончательный выбор остаётся за бизнесом.
+
+### Рейтинг готовности
+
+Геймификация направлена на заказчика: понятные условия повышают оценку и показывают, что ещё стоит уточнить.
+
+| Критерий | Максимум |
+| --- | ---: |
+| Цель мероприятия | 10 |
+| Аудитория и число участников | 10 |
+| Дата, формат и площадка | 10 |
+| Бюджет и оплата команды | 10 |
+| Ресурсы бизнеса | 10 |
+| Обязанности команды | 20 |
+| Результат работы | 10 |
+| Критерии приёмки | 20 |
+| **Итого** | **100** |
+
+ИИ определяет состояние каждого критерия: информация отсутствует, частичная или достаточная. Сервер применяет фиксированный коэффициент **0 / 0,5 / 1** к весу критерия и складывает баллы. Рейтинг оценивает ясность текста, а не гарантирует успешность мероприятия или достоверность сведений.
+
+В текущем MVP оценка отображается в редакторе. Её сохранение вместе с публикацией пока не подключено.
+

+## 5. Архитектура
+
+```text
+Браузер: Next.js / React
+│
+├── Редактор задачи
+│   ├── localStorage: черновик, вопросы, ответы, карточка
+│   ├── POST /api/clarify  ──► OpenAI: уточняющие вопросы
+│   ├── POST /api/improve  ──► OpenAI: подготовка карточки

+└── Supabase JS + пользовательская сессия

+## 6. Установка и запуск
+
+### Требования
+
+- Node.js 24 LTS и npm. Разработка велась с Node.js 24 и npm 11.
+- Ключ OpenAI API с доступом к выбранной модели и доступным балансом.
+- Проект Supabase с таблицами `tasks`, `applications` и настроенными RLS-политиками.
+
+### Шаг 1. Клонировать репозиторий
+
+Скопируйте URL этого репозитория через кнопку **Code** на GitHub и выполните:
+
+```bash
+git clone <URL_ЭТОГО_РЕПОЗИТОРИЯ>
+cd hack-465d0595-lanren/web
+npm ci
+```
+
+Все дальнейшие npm-команды выполняются в папке `web`. Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd` вместо `npm`.
+
+### Шаг 2. Настроить переменные окружения
+
+Создайте `web/.env.local` рядом с `package.json`:
+
+```dotenv
+OPENAI_API_KEY=your_openai_api_key
+OPENAI_MODEL=gpt-4.1-mini
+NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
+NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your_supabase_publishable_key
+```
+
+Замените значения-заглушки своими. Для браузера используется **publishable key**, не `service_role` и не секретный ключ Supabase. Не добавляйте префикс `NEXT_PUBLIC_` к ключу OpenAI.
+
+`.env.local` исключён из Git правилами проекта. Не публикуйте реальные ключи в README, коммитах или скриншотах.
+
+### Шаг 3. Настроить Supabase
+
+Для подготовленного демо-проекта таблицы уже создавались через SQL Editor. Для другого проекта потребуется воспроизвести схему и политики из приложения ниже.
+
+1. Создайте проект Supabase и получите его URL и publishable key.
+2. В настройках **Authentication** включите **Anonymous Sign-Ins**: приложение использует анонимные сессии для публикаций и откликов.
+3. Создайте таблицы `tasks` и `applications`, включите RLS и соответствующие политики доступа.
+4. Укажите реквизиты проекта в `.env.local`.
+
+### Шаг 4. Запустить приложение
+
+```bash
+npm run dev
+```
+
+Откройте [главную страницу](http://localhost:3000) или [каталог](http://localhost:3000/catalog).

+Проверка чтения таблицы задач: [диагностический маршрут](http://localhost:3000/api/db-check). Успешный ответ содержит `ok: true`. Эта проверка сама по себе не подтверждает возможность публикации и отправки откликов.

+После изменения `.env.local` перезапустите dev-сервер.

+## 8. Данные и интеграции
+
+### Источники данных
+
+Приложение использует сведения, введённые бизнесом и студентами. Внешние каталоги мероприятий, парсинг сайтов и готовые обучающие датасеты не подключены.
+
+### OpenAI
+
+- `/api/clarify` передаёт первоначальное описание для генерации вопросов.
+- `/api/improve` передаёт описание и ответы для подготовки карточки.
+- `/api/evaluate` передаёт название и текст карточки для оценки полноты.
+- Ответы запрашиваются в структурированном формате и проверяются по схеме.
+- В запросах установлено `store: false`; это не следует трактовать как самостоятельную гарантию полного отсутствия хранения данных провайдером.
+- В инструкциях модели запрещено выдумывать факты. Результат всё равно требует проверки человеком.
+
+### Supabase
+
+| Таблица | Основные данные |
+| --- | --- |
+| `tasks` | Автор, название, описание, статус, поле рейтинга, дата создания |
+| `applications` | Задача, автор отклика, команда, предложение, контакт, статус, дата создания |
+
+Публичному каталогу доступны опубликованные задачи. При настройке приведённых ниже политик отклики могут читать только их авторы и владельцы соответствующих задач. Контакты не выводятся в открытом каталоге.
+
+Черновик хранится отдельно в localStorage браузера. Кнопка новой задачи очищает локальный редактор, а не записи Supabase.

+## 9. Ограничения текущей версии
+
+- **Выбор команды:** кабинет заказчика, список откликов и подтверждение выбранной команды ещё не реализованы.
+- **Рейтинг в каталоге:** UI оценивает карточку, но публикация пока не сохраняет результат в `readiness_score`. Каталог умеет сортировать по этому полю, однако без сохранённого значения показывает отсутствие рейтинга.
+- **Анонимные сессии:** полноценной регистрации, постоянных профилей и восстановления доступа нет. Очистка данных браузера может лишить пользователя доступа к прежней анонимной сессии.
+- **Черновик:** хранится на одном устройстве и в одном профиле браузера; синхронизации нет.
+- **Повторная публикация:** кнопка защищена от повторного нажатия в текущем состоянии страницы, но после перезагрузки публикация того же текста может создать дубликат.
+- **Редактирование публикации:** правки в локальной карточке не обновляют уже опубликованную запись.
+- **Список пробелов:** ручные изменения текста не пересчитывают `missingInformation`; для новой проверки нужно повторно сформировать карточку.
+- **Каталог:** загружается до 50 задач; поиска, фильтров и постраничной навигации пока нет.
+- **ИИ:** зависит от сети, доступности модели, баланса и лимитов OpenAI. Не проверяет реальность площадки, бюджета и обещаний заказчика.
+- **Готовность к публичному запуску:** нужны ограничения частоты запросов к AI-маршрутам, защита от спама, модерация и полноценная модель аккаунтов.
+- **Область ответственности:** сервис готовит задания и сохраняет отклики; он не бронирует площадки, не проводит оплату и не гарантирует исполнение работ.

+## Приложение: схема для нового проекта Supabase
+
+Ниже — установочный SQL, соответствующий модели данных MVP. Он предназначен для **нового проекта без таблиц `tasks` и `applications`**. Не запускайте его повторно поверх существующих таблиц. Схема ранее настраивалась вручную; этот блок не является экспортом текущей удалённой базы или автоматически проверенной миграцией.
+
+Выполните блок в SQL Editor нового проекта Supabase:
+
+```sql
+begin;
+
+create table public.tasks (
+  id uuid primary key default gen_random_uuid(),
+  owner_id uuid not null references auth.users(id) on delete cascade,
+  title text not null check (char_length(trim(title)) between 1 and 200),
+  description text not null check (char_length(trim(description)) between 20 and 12000),
+  status text not null default 'draft' check (status in ('draft', 'published', 'closed')),
+  readiness_score integer check (readiness_score between 0 and 100),
+  created_at timestamptz not null default now()
+);
+
+create index tasks_owner_id_idx on public.tasks(owner_id);
+create index tasks_catalog_idx
+  on public.tasks(readiness_score desc nulls last, created_at desc)
+  where status = 'published';
+
+alter table public.tasks enable row level security;
+revoke all on public.tasks from anon, authenticated;
+grant select on public.tasks to anon, authenticated;
+grant insert (owner_id, title, description, status) on public.tasks to authenticated;
+grant update (title, description, status) on public.tasks to authenticated;
+
+create policy "Public can read published tasks" on public.tasks
+  for select to anon, authenticated using (status = 'published');
+create policy "Owners can read their tasks" on public.tasks
+  for select to authenticated using ((select auth.uid()) = owner_id);
+create policy "Owners can create their tasks" on public.tasks
+  for insert to authenticated with check ((select auth.uid()) = owner_id);
+create policy "Owners can update their tasks" on public.tasks
+  for update to authenticated
+  using ((select auth.uid()) = owner_id)
+  with check ((select auth.uid()) = owner_id);
+
+create table public.applications (
+  id uuid primary key default gen_random_uuid(),
+  task_id uuid not null references public.tasks(id) on delete cascade,
+  applicant_id uuid not null references auth.users(id) on delete cascade,
+  team_name text not null check (char_length(trim(team_name)) between 2 and 100),
+  proposal text not null check (char_length(trim(proposal)) between 20 and 3000),
+  contact text not null check (char_length(trim(contact)) between 3 and 200),
+  status text not null default 'pending' check (status in ('pending', 'selected', 'rejected')),
+  created_at timestamptz not null default now(),
+  unique (task_id, applicant_id)
+);
+
+create index applications_applicant_idx on public.applications(applicant_id);
+alter table public.applications enable row level security;
+revoke all on public.applications from anon, authenticated;
+grant select on public.applications to authenticated;
+grant insert (task_id, applicant_id, team_name, proposal, contact)
+  on public.applications to authenticated;
+
+create policy "Applicants can read their applications" on public.applications
+  for select to authenticated using ((select auth.uid()) = applicant_id);
+create policy "Task owners can read applications" on public.applications
+  for select to authenticated using (
+    exists (
+      select 1 from public.tasks
+      where tasks.id = applications.task_id
+        and tasks.owner_id = (select auth.uid())
+    )
+  );
+create policy "Applicants can apply to open tasks" on public.applications
+  for insert to authenticated with check (
+    applicant_id = (select auth.uid())
+    and exists (
+      select 1 from public.tasks
+      where tasks.id = applications.task_id
+        and tasks.status = 'published'
+        and tasks.owner_id <> (select auth.uid())
+    )
+  );
+
+commit;
+```
+
+Роль `authenticated` также используется анонимными пользователями Supabase Auth. Поэтому доступ ограничивается не только ролью, но и сравнением `auth.uid()` с владельцем записи. Клиенту не предоставляется право записывать рейтинг и менять статус отклика: соответствующая серверная логика остаётся отдельным этапом разработки.
